# Linux Docker + runc slice

This checkout implements one real backend: an explicit local Docker Engine endpoint running a Linux image with the `runc` runtime. The SDK does not pull images and does not expose bollard types. Callers provide the image, endpoint, resource limits, isolation policy, and output bounds; the owner label is generated internally per sandbox.

The adapter sets memory and swap, milli-CPU to nano-CPU, pids, a bounded tmpfs workspace, read-only root, `none` networking, `no-new-privileges`, and `ALL` capability drop. It creates no host binds, volumes, credentials, or ports. Workspace files are staged from the existing capability-scoped `Workspace`. The guest file transport requires Python 3 and rejects symlinks during running-phase file operations.

Before create succeeds (and before start), the adapter inspects the created container and rejects any mismatch in memory, memory-plus-swap, nano-CPU, pids, read-only root, init, runtime, numeric guest user/group, working directory, `none` network mode and network-disabled flag. It requires exactly `ALL` capability drop, no added capabilities, non-privileged mode and only the enabled no-new-privileges security option. Host binds, explicit mounts, inherited/image volumes, device mappings/requests/cgroup rules, published ports, custom DNS and extra hosts are forbidden. IPC and cgroup namespaces must be private; PID, UTS and user namespace modes must remain unset. Automatic removal, restart and OOM-killer disabling are forbidden; shared memory stays at 65536 bytes.

The only configured tmpfs must be the requested workspace, with exactly `rw,nosuid,nodev`, the requested UID/GID, `mode=0755`, and the exact byte size. Option order is irrelevant. Inspect's mount list may omit that tmpfs, or report it once as writable tmpfs at the same destination with no host source; no other mounts are accepted. Empty optional lists may be absent, capability `ALL` is case-insensitive, and Docker's `no-new-privileges`, `no-new-privileges:true` and `no-new-privileges=true` spellings are equivalent. Other unrecognized policy rewrites fail closed rather than weakening create flags. A mismatch returns an engine error carrying the created ID into the existing owned-container cleanup path; cleanup failure retains ownership for retry.

This is a pre-start check of a trusted daemon's inspect response, not independent proof of kernel enforcement or protection from later privileged daemon/host changes. Docker-managed runtime mounts (such as `/proc`, `/dev` and generated resolver files) are not enumerated by that mount list and are not claimed absent. Real integration assertions additionally check guest UID/GID, effective capabilities and no-new-privileges, loopback-only interfaces, read-only root, and the workspace's tmpfs type, flags and size; private policy tests cover rejected inspect deviations without substituting a mock daemon for backend tests.

`CommandRequest` uses argv form, bounded stdout and stderr, and a required timeout. Timeout, output overflow, and cancellation destroy the entire owned container so descendants cannot survive. Dropping the create future retains the generated name and owner label and recovers only a matching container. Cleanup errors retain ownership and are returned; retry `destroy` is required. Start and lifecycle operations also use the configured I/O timeout and may destroy the container when the engine call cannot be accepted safely.

The ignored integration test requires `CIRCUS_DOCKER_SANDBOX=1` and `CIRCUS_DOCKER_ENDPOINT`; it must run against a real Linux Docker Engine with cgroup v2 and have the Docker CLI available. `CIRCUS_DOCKER_IMAGE` optionally overrides the default `python:3.12-slim` image and must refer to a local Linux image containing Python 3. Tests explicitly destroy each sandbox, assert destroyed phase and no container ID, and use CLI inspect against the configured endpoint to verify absence; emergency fixture cleanup is not teardown evidence. The example is `docker_sandbox` and also requires an endpoint. Run it with `cargo test --locked --test docker_sandbox -- --ignored`.

Snapshot, Docker commit, HTTP, Git, environment resolution/pull, pools, and other runtimes are planned but not implemented. A read-only root plus tmpfs workspace would not preserve workspace writes in a Docker commit; a future snapshot must archive and restore files.
