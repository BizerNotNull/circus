# 交付计划

本文把已明确的沙箱需求映射为可验证验收和小 PR 顺序。它是计划，不是已实现能力。本地编辑、工具安装和主机 Docker 可达都不能写成合并完成。

不发明尚未实现的 URL、RPC 方法或字段名。进程内领域类型先行；HTTP 是后续传输，不在首个 API 中预设路径。

## 非目标

- 不把 Docker、Kubernetes、containerd、runc、gVisor、Kata、Firecracker 全部实现。候选不是全量支持。
- 不创建空适配器来声称支持。
- 不修改 `circus-paseo/`，也不把 Paseo CI 当作沙箱验证。
- 不把 OpenSandbox 的架构、端点或测试通过状态复制为本仓库能力。下文上游引用不是全库审计。
- 配置持久化仍未选定，这些 PR 不引入数据库或 ORM。

## 支持策略

建议的首个真实适配只有 Linux 上的 Docker + runc。其余后端保持未实现，直到有单独的产品选择和真实运行证据。

池、预启动和快照不从用户范围删除，但也不进入首个适配。没有真实后端和干净检出保证时，不得标记为已支持。

## 小 PR 顺序

质量基线、安全基线和首个工作区 crate 都从 `main` 并行，互不以对方合并为前置。其余实现依赖已合并到 `main` 的契约，而不是另一台机器上的未合并副本。

每个 PR 单独验收，证据写在该 PR，不写进本文：

- 该提交上已经存在的适用工作流没有被跳过，失败没有被吞掉。尚未进入该提交的扫描不能写成已运行，也不能写成本 PR 已有结果。
- 安全基线合并之后，新增依赖要经过 dependency review。合并之前不能把尚未落地的扫描写成已通过。
- 许可证允许列表 PR 合并后，新增依赖还必须通过该扫描。此前不能把 dependency review 写成许可证策略。
- 改到的文档落在 QA 白名单内，并由 `npm --prefix circus-sandbox/qa run check` 覆盖。质量基线合并前，其他分支不把这条检查写成自己已有。
- `main` 需要 1 个非作者批准审查。作者不能自批，不得绕过保护。工作流存在不等于 required status check。本地或 CI 变绿本身不是合并完成。

### 1. 质量基线（本 PR）

分支：`main` → `ci/sandbox-quality-baseline`。依赖：无。不阻塞 `feat/capability-workspace`，也不阻塞安全基线。

范围：`circus-sandbox/qa`、本文、工程说明、仓库导航、`.github/workflows/sandbox-quality.yml`、`.github/codeql/sandbox-qa.yml` 和 `.github/scripts/sandbox-actionlint.sh`。本分支不新增 Cargo 工程，也不包含安全工作流、gitleaks 脚本、actions CodeQL 配置、Dependabot 或 `.gitleaksignore`。

验收：根目录可以执行工程说明中的 `npm --prefix circus-sandbox/qa ci`、`npm --prefix circus-sandbox/qa audit --audit-level=low` 和 `npm --prefix circus-sandbox/qa run check`。`ci` 和 `audit` 不是 package script。actionlint 只检查质量工作流和它自己的脚本。`CodeQL QA` 分析本 PR 的 `circus-sandbox/qa`，语言是 `javascript-typescript`，`build-mode` 为 none。本 PR 不附密钥扫描、dependency review 或 actions CodeQL 结果。

QA 运行时固定 Node.js 24.18.0，与 `circus-sandbox/qa/.node-version` 一致，不用 Paseo 的 Node 22。Markdown 检查直接调用 markdownlint 0.42.0 的 promise API。manifest 不引入 markdownlint-cli2 的 glob 链，也不用 advisory ignore 或降级处理 braces。审计输出记在本 PR，不在本文写成已通过。

### 安全基线（并行 PR）

分支：`main` → `ci/sandbox-security-baseline`。不依赖质量基线合并，也不包含 QA 源码。本文不链接该分支才有的文件。

范围以该 PR 为准。计划边界是：CodeQL 只有 actions，路径不覆盖 Paseo，也不分析 QA JavaScript；那是本质量 PR 的 `CodeQL QA`，两边都不把对方合并当作前置。Dependabot 只开 `github-actions` 更新。dependency review 仍只在 `pull_request` 上失败即失败，不要把它设成 `merge_group` 的必需检查。密钥扫描使用该 PR 自己的入口；精确例外留在该 PR，不在本检出复制第二份忽略文件。

验收记在该 PR。本质量 PR 不代填它的扫描结果。

`circus-sandbox/qa` 的 npm 依赖更新不在本 PR 新建 Dependabot。等安全基线合并后，再在已有配置上追加 npm 目录，避免两份配置冲突。

### 2. 独立能力：cap-std 临时工作区

分支：`main` → `feat/capability-workspace`。不依赖文档或安全基线合并。

范围：首个真实 crate，不是空壳。提供 cap-std 受限的临时工作区文件 API，包含有界读写、显式可重试且幂等的清理、真实 example 与测试，以及 Apache-2.0 沙箱许可证。使用 Rust/Cargo 1.99.1。没有容器、服务或后端适配器。Rust CodeQL 在该 PR 自己的工作流里，不依赖本质量基线，本质量基线也不等待它。

验收：读写不能逃出已授权根；超限失败；清理可重复调用，失败可重试且不能只记日志；测试和 example 运行的是该文件 API，而不是占位。未合并前，`main` 没有这个 crate。没有该 crate 的 CodeQL 分析就不能写成已分析。

### 许可证允许列表

依赖：第一份需要约束的锁文件。不依赖运行时。

范围：沙箱直接依赖的显式许可证允许列表。未配置、无法识别或不在列表内即失败。不扫描 Paseo 来给沙箱发通过。

验收：新增直接依赖都能对应到允许的许可证，或该 PR 更新列表并说明原因。空扫描结果不是通过。

### 3. 进程内领域 API 与生命周期

依赖：文件操作消费 capability-workspace 契约，不另写一套路径访问。不依赖质量基线合并。

范围：创建、执行、文件、销毁的领域类型和合法状态转换。不引入 HTTP，不加入空的 Docker/Kubernetes 适配器。

验收：非法转换失败；领域错误可匹配；公开 API 没有后端类型。没有隔离测试就不能写隔离已支持。

### 显式配置

依赖：进程内领域类型。

范围：隔离级别、资源限制、权限和超时没有安全向的隐式默认。缺少必填项是错误。不引入数据库，也不提前选定持久化。

验收：缺省安全项被拒绝；显式配置会生效。具体配置键在该 PR 写明，本文不预告。

### 健康与日志

依赖：进程内生命周期。

范围：日志使用沙箱指南选定的 tracing，不另起日志框架。健康是领域结果，不是未实现的 URL。此 PR 不暴露抓取端点。

验收：失败、取消和销毁能关联到日志；健康结果能区分不可用与未实现。没有真实后端时不发布运行指标。

### 4. environment 与 Git 工作区

依赖：capability-workspace 的文件契约。

范围：OCI 镜像、基础环境、依赖准备，以及 Git clone、worktree 或代码副本。不实现池，不替换 cap-std 边界。

验收：路径逃逸失败；Git 参数不经过 shell；创建失败和取消会回收工作区；阻塞调用不占异步执行线程；环境标识不跨租户复用。

### 5. 首个真实适配：Docker Linux + runc

依赖：后续运行时必须先消费 workspace 契约，再开始开发。不依赖质量基线合并。

范围：只实现这一组合。Kubernetes、containerd、gVisor、Kata、Firecracker 不在本 PR。

验收：

- 在 Linux Engine 上用真实 Docker 完成创建、执行、文件操作和销毁。引擎可达不是本项已经通过。
- 文件操作消费 capability-workspace 契约，不在适配器里另建宿主路径访问。
- 测试只删除自己创建的容器和卷。禁止全局 prune；现有无关容器不得被清理。
- 资源限制、pids、内存、CPU、`no-new-privileges`、capability drop 和 runtime 名称来自显式配置。
- 请求其他运行时时明确拒绝，不静默降级。
- 创建失败会跟踪已出现的容器标识并强制回收；回收失败必须返回给生命周期，不能只写日志。
- 删除或 TTL 回收失败时保留尚未删除的依赖并允许重试；并发删除不产生第二次成功清理的假成功；停止调用的传输失败后仍要强制删除，并报告最终归属。
- 取消向整个进程组发送终止并等待结束，然后再汇合输出。

### 部署边界

依赖：Docker Linux + runc 适配。

范围：写明该适配的部署前提和不支持的部署。不提供虚构安装器，不把候选后端写成可选部署。

验收：文档与该适配的实现一致。验证只清理自己创建的资源，禁止全局 prune。不支持的 runtime 明确拒绝。

### 文件系统快照

依赖：Docker Linux + runc 适配。这是该适配选定的快照语义，不是内存或进程检查点。

范围：只承诺容器可写层的文件系统快照。成功结果必须能恢复所声明的文件写入。不承诺保留运行中的进程或客户机内存。

验收：不支持可靠提交的运行时必须失败关闭，不能发布成成功。文件系统 diff 无法检查时也失败关闭。需要内存暂停或进程恢复的能力另立项，不能由本快照暗示已经支持。

取舍：Docker commit 能在支持的 Engine 上验证文件写入；它看不到客户机内存。这是首个适配的明确选择，不是把更强的检查点悄悄降级。

### 运行指标

依赖：同一适配已有真实运行证据。

范围：冷启动、失败和资源回收有可核对的计数。不发明未实现的抓取 URL。

验收：指标能对应到一次真实运行。没有运行证据的数字不能标成已支持。

### 6. HTTP 传输

依赖：进程内领域类型。不阻塞首个真实适配的证明，但不得早于领域类型。

范围：确认需要 HTTP 后，只用沙箱指南选定的 axum。不复制上游路径。

验收：同一套请求、结果和错误；响应不泄露后端类型；未实现的操作返回明确错误，而不是空路由假装支持。端点在该 PR 实现时确定，现在不预告。

### HTTP 认证与 OpenAPI

依赖：HTTP 传输。

范围：管理面默认不能匿名。请求和响应按该 PR 提交的 OpenAPI schema 校验，schema 与实现不一致即失败。路径写在 schema 中，本文不预告。

验收：未认证请求被拒绝；错误体不泄露后端类型；未写入 schema 的操作不能假装支持。

### 代码快照与暖池干净检出

依赖：文件系统快照与 workspace 契约都已存在。此项仍是保留需求，不是可选删除，也不是文件系统快照的别名。

范围：预启动或暖池，以及代码工作区快照。不因此扩大到其他运行时，也不把内存检查点补进 Docker 文件系统快照。

代码快照语义：

- 代码快照是新工作区的起点，不是原租用的继续，也不是客户机内存的副本。
- 成功结果必须恢复出所声明的代码或文件写入。恢复不出写入却报告成功，视为失败。
- 当前适配器不能可靠完成该快照时必须拒绝。禁止静默改用另一运行时后再报告成功。
- 失败由生命周期记录状态和资源归属。删除快照记录与删除底层产物的差异在该 PR 写明。

暖池干净检出语义：

- 暖实例只能在检出干净后租出。干净指代码、Git 状态、文件和凭据都不含上一租户残留。
- 不能证明干净检出时不得租出，必须通过同一生命周期回收或销毁。
- 冷启动与复用都要测量；复用测试必须证明跨租户不泄露。
- 池不建立第二套状态机，也不绕过销毁和取消的回收路径。

现在不为这两项命名端点或配置键。

### 文档边界复核

依赖：每个已合并的能力 PR。

范围：支持、不支持和未实现都能在工程说明或本文中找到。`npm --prefix circus-sandbox/qa run check` 覆盖白名单。不把计划改写成已实现。

验收：所声称的命令和边界能在文档中找到。未实现的候选后端仍标为未支持。
